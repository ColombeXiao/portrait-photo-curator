# 审片 JSON：每批一份的结构约定

`_work/batches/batch_001.json` 给出待审核的照片 ID、相对路径和预览位置。对照这些路径逐张看图，结果写到 `_work/reviews/batch_001.json`。必须是 UTF-8 编码、合法 JSON。

完整示例（**纯粹演示字段，不能拿此文字充当真实照片的审片内容**）：


## 字段要求

- 每项必须恰好包含 `id` 与 `grade`（`A`、`B`、`C`）。ID 按清单原样填写。
- `A` 必须有非空 `title`、`verdict`、`strengths`（**至少 3 项**，每项 `observation` / `principle` / `repeat` 非空）、`next_shoot`（至少 1 条）。三个优点可来自相近方面但要有不同且真实的观察；若实在无法写出三项，必须复看并审视 A 是否成立。
- `B` 必须有非空 `title`、`potential`、`issues`（至少 1 项，含 `observation` / `impact` / `principle` / `capture_prevention`）；`xingtu` 需含 `goal`、至少一个 `steps`（每步含 `tool` / `action` / `start` / `reason` / `check`）、`avoid`（至少 1 条）与 `export`；`learning` 至少 1 项（`rule` / `applied` / `next_shoot`）；`reshoot` 至少 1 条。
- **C 对象只能有** `{"id":"Pxxxx","grade":"C"}` **这两个字段。**不要写备注、废片成因、置信度等。即使在工作 JSON 中也不能写个片理由。
- 各段须和单张图片对应；参数只写“建议从 XX 起试”并按可见画面调整，不要编造拍摄设置或官方醒图固定位置。
- 批次文件不是脚本自动审片结果，**必须由具备图像理解能力的 Codex 逐张观察后填写**。脚本只检查格式、分类并生成文档。
